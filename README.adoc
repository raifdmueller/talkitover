== Was das ist

Dein Leser bringt sein LLM mit. Deine Site reicht ihm den Inhalt. Du hostest
kein Modell, zahlst keine Token und siehst nie, was er fragt.

Konkret: ein Web Component von 12 KB, das du in dein Repo kopierst, und ein
Generator, der aus deinen Inhalten Textfassungen und den Prompt baut. Ein Klick
öffnet Claude oder ChatGPT mit einem Prompt, der deine Seiten benennt — und das
Gespräch beginnt mit einer Frage an den Leser, nicht mit einer Zusammenfassung.

Nichts davon läuft zur Laufzeit gegen diese Site. Der Button funktioniert
weiter, wenn es uns nicht mehr gibt.

== Loslegen

. {site}/einstieg.md[Einstiegs-Prompt] kopieren.
. In Claude Code einfügen, im Repo deiner Site.
. Pull Request reviewen und mergen.

Claude Code erkennt den Generator deiner Site selbst und wählt das passende
Rezept. Ist er nicht eindeutig, fragt es. Kennt es ihn nicht, bricht es ab und
sagt warum — es improvisiert nicht.

== Warum es so gebaut ist

Beim Talkable-Machen der ersten Site sind vier Annahmen gefallen. Die
wichtigste:

[quote]
____
Das LLM des Lesers holt eine URL, die *in der Nachricht stand*, die es bekommen
hat. Eine URL, die es nur _in_ einem geholten Dokument gefunden hat, verweigert
es.
____

Geprüft als `text/plain`, `text/markdown` und HTML mit echten `<a href>` —
identische Verweigerung. Kein Format-Problem, sondern eine Regel über die
Herkunft. Ein Index aus Links listet eine Site also, ohne sie aufzuschließen;
die Adressen müssen in den Prompt.

Das erklärt fast alles am Aufbau: warum der Generator die Seiten benennt, warum
er das URL-Budget misst statt zu raten, und warum lange Inhalte gebündelt
werden, statt verlinkt.

Der Rest steht auf {site}/erkenntnisse/[Was wir gemessen haben] —
mit den Zahlen, und mit dem, was noch ungemessen ist.

== Entwicklung

[source,bash]
----
npm test                # 57 Tests, keine Abhängigkeiten
npm run check:sites     # prüft jeden Galerie-Eintrag gegen die echte Site
npm run build:talkitover # erzeugt Textfassungen und Prompt (zwischen den Builds)
----

Die Website ist Jekyll aus `docs/`, gebaut von GitHub Pages:

[source,bash]
----
jekyll build -s docs -d _site   # erzeugt das HTML
npm run build:talkitover        # liest es, schreibt Textfassungen und Prompt
jekyll build -s docs -d _site   # rendert den Button daraus
----

Zwei Durchläufe, weil Jekyll nichts einsetzen kann, was es noch nicht gibt.

Rezepte und Prompts tragen bewusst kein Front Matter. Jekyll kopiert sie
dadurch unverändert — Claude Code bekommt Rohtext, keine HTML-Hülle.
